# 影子对照：如何验证判断是否增加价值

工具：`python3 scripts/shadow_compare.py --input <锁定研究输入.json> --output <结果.json>`。

本工具只算**单个载体的标准化研究路径**，没有券商接口、不推算用户真实交易，也不是完整组合/账户绩效系统。主线筛选质量先使用历史审计中的同锚T+5/10/20读数诊断，不把它转换成可成交收益。

## 数据合同

JSON顶层：

- `mode`: `historical_diagnostic` / `prospective_shadow` / `synthetic_test`。过去数据重读只能前者，测试夹具必须后者。
- `asset`: 单一真实载体代码；前瞻记录中的 `research_asset` 必须与它一致，禁止事后替换赢家。
- `source`: 数据来源与已保存文件位置；`price_basis`: `adjusted_consistent`或`unadjusted_no_actions`，后者必须核过无除权分红事件。
- `calendar`: 来自真实交易日历的完整交易日数组，ISO日期，不允许用行情缺行后的日期列表冒充。
- `prices`: 与calendar逐项对应的`date/open/close/buyable/sellable`。买卖可执行性必须有停牌/涨跌停和报价证据，不能默认true来挽救数据。缺开盘/可执行性只做价格诊断，不运行收益对照。
- `cost_bps`: 事前选定、所有方法一致的单边比例费用与滑点假设（不是已验证券商费率）；须做正常与较高成本两档敏感性。
- `strategies`: 至少两组`name/signals`；signal含`date/decided_at/target/evidence_ref`。target是研究资金中0至1的假设投入比例，与真实仓位无关。记录日期唯一，交易日信号须在09:30前或15:00后形成；周末/跨午夜按实际决策时间等待严格晚于有效录入时刻的开盘。signal.date 是 decided_at 的 +08 日期，不能用前一行情日代替；账本 data_date 单独记录真实行情日。

## 固定比较规则

先把同入场、同载体持续持有作为退出环节基线，再考虑少量已锁定价格趋势规则。方法名称、具体条件和初始时点在数据揭晓前固定，不在结果后选最好基线。没有真实Astra日更记录时，不生成“AI策略”假信号；历史留有完整原建议的部分也须标历史诊断。

信号在实际有效时间之后的第一个声明交易日开盘研究执行；无法执行则记未执行，**不自动顺延追单**；末日信号待下个交易日，不提前成交。单日最多一次调仓，无当日买入卖出。无新信号时模拟持有当前头寸，不代表AI当日作出继续持有建议。未复盘日保留缺口，日常重启时必须重新核查纪律。

计入比例交易成本、跳空，期末仅按收盘计价不强制卖出。现金收益暂设0。**未建模最低佣金、整数交易单位、盘中可成交量和复杂公司行动**；因此结果只能用于同标的机制比较，不能直接形成个性化资金方案。展示风险与平均暴露，不只展示收益。若真实实施受这些限制影响，补证据或标未验证，不能宣称通过真钱验收。

## 资格

输出永远区分`research_simulation_only`与`profitability:not_established`。运行成功不晋级盈利资格。验证的最低覆盖、主题去重与评审见项目运行合同；看过的历史无法成为新版本未见样本。停止无效假设时保留原版本与负结果。

## 前瞻收据与完整序列

`prospective_shadow`必须提供 `evaluation_as_of`（带时区的实际评估截止时间，不早于末日收盘）。每个strategy声明`theme_id/method_version/journal`；分别使用投资运行配置的影子主账本及两份baseline_journals，不把不同方法塞在同一建议链。signal必须给`decision_id`，它的目标、资产、时刻必须逐项匹配系统录入过的shadow记录，且包含窗口内该主题方法的全部研究目标记录，不能挑掉退出。研究期从事件初始空头寸开始，不能隐去之前仍持有的头寸。

有效时刻取账本系统`recorded_at`与决策时刻的较晚者，哈希链本身不能证明人为提供的行情和证据真实。前瞻记录先锁入账本，后来才填价格与可交易性；不能在价格揭晓后补填旧日信号。不同方法各自事前记录相同资产和不同研究目标。`hold`保持已有单位头寸，不因价格变化重算成买卖；非前瞻输入若不写action则明确解释为目标再平衡，不能冒充原AI持有动作。
