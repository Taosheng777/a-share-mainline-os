# 金融专家模式编排（多 agent 蜂群 · 决策支持）

## 立场（铁律）
先完成场内与标的本身的五维研究（技术/资金/基本面/消息/估值），再按 `decision-support.md` 形成 AI 建议层。单标的纯研究默认不读取个人账户；用户问“我该怎么做”、持仓处理、仓位建议，或从载体名单接力时，自动走 personal-aware 路由，叠加当前持仓与账户风险结构。**账户纪律以 `<vault_root>/01-纪律卡.md` 当前三条线为准，现读且禁止固化阈值。**仍守：不下单、不编数据。

## 门控（硬）
两条进入路径，二选一：
1. **用户当轮明说**"用/开启金融专家模式""开专家模式"或同等明确表达 → 按本 skill 定义即等同于同意「5 个 sub-agent + 新闻/研报/行业接口」，**不必再 AskUserQuestion 二次确认**；执行前用一句话短提示说明"将按 5-agent 蜂群运行，较慢较贵"，然后直接开跑。
2. 用户只说了买入动作词或深度决策需求（要不要买 / 进场点 / 买入信号 / 止盈止损 / 目标价 / 仓位建议 / 帮我深度研判）但**没点名专家模式** → 用 AskUserQuestion 问，**立即结束本轮**，只有用户在下一轮真实选择"开启"才可进入。

措辞只是"盘中看看 / 帮我分析 / 怎么样"→ 两条路径都不成立，留在常规档。本会话历史里没有上述真实记录 = 不得进入。**严禁把自己的推断/复述当作用户确认；不得在同一轮自问自答后进入。**

## 编排（首席 = 当前会话；蜂群 = Agent 工具派发）
1. 首席读 `agents/chief-analyst.md`，明确标的、分析目标。
2. **并行派 5 个 sub-agent**（Agent 工具，subagent_type 用 general-purpose 或 claude），各自传入对应 `agents/<name>.md` 的 prompt + 标的代码简称 + 数据日：
   - technical-agent / fund-flow-agent / news-research-agent / fundamental-industry-agent / risk-agent
   - 每个 sub-agent 自己 `source ~/.zshrc` 跑对应 CLI（行情技术资金走 hithink；消息/研报/行业走 `skillhub-usage.md` 的命令）。
   - 五个 sub-agent 职责互斥；首席不重复完整五维取数，只做必要核验与汇总。并发受限时**分批派发**（不算降级），但不得合并维度、减少总数、或由首席补做缺失维度。
3. 首席**收齐 5 份独立结果**（缺一不可）→ 汇总裁决：
   - 综合裁决：进场信号 成立/不成立/观察 + 置信度。
   - 技术、资金、消息研报、基本面行业按 `-2..+2` 评分；默认权重 `25% / 30% / 20% / 25%`，展示评分、权重、加权贡献、加权总分和完整公式。
   - 风险标签为通过/警示/否决，不参与数值加权并独立行使否决权。
   - 买入信号 / 危险(回避)信号（市场级）。
   - 按 `decision-support.md` 给 AI 行动倾向、证据权重、主要反方与改判条件；能审计才给目标区间，personal-aware 路由再给风险预算仓位区间。
4. 若从 stock-screener 的**载体名单**接力，读取 `references/selection-handoff.md`：把五维结果和首席裁决写回**所属主线页**，给出载体强弱排序与每一位的排序理由。载体是为主线服务的，**不评"唯一首选"**——排序本身就是结论。
5. 按 `references/report-template.md` 产出载体研判，写入主线页的「载体清单」「参考条件位」「AI 决策建议」「估值与情景区间」「AI 仓位建议」。**v3 不新建 `07-交易决策/`**（该目录已归档），也不写 `08-下个交易日/`、`09-选股池跟踪/当前观察候选.md`。
6. 参考条件位只表达技术锚点；外部机构目标、AI 估值 / 情景区间和技术位必须分开。仓位按风险预算法计算，属于带数据日的 AI 建议，不写入纪律卡、不冒充当前持仓。
7. 用户提供最新券商截图或口头持仓概况后，才做差异对账：只更新持仓卡的标的 / 角色 / 所属主线 / 用户已确认止损，以及主线页「我的操作」区的新增 / 清仓 / 数量变化 / 角色变化；不追溯逐笔成交，不做算术核对，不算净值绩效。

## 降级规则（防静默冒充，2026-07-21 与 Codex 版对齐）
- **不允许**把"当前会话顺序完成五维取数"静默写成金融专家模式。
- sub-agent 派发失败或超时 → **先合理重试**；只有 Agent 工具不可用、或重试后仍未收齐五份独立结果，才进入降级分支。并发槽不足而分批运行**不属于降级**。
- 降级前必须先告知用户："无法完成 5 个子代理蜂群，本次只能做单代理五维复核"，**等用户同意后才能继续**（用 AskUserQuestion 问，本轮结束等真实回复）。
- 用户同意降级后，输出和落盘标题附近必须标注**"单代理复核，非蜂群专家模式"**。
- 用户未同意降级 → 停在取数/摘要层，**不给专家模式裁决、不落盘交易决策**。
- 用户主动要求"快速版/不要子代理/单代理复核"→ 可直接走单代理五维取数，但输出和落盘同样标注"非蜂群专家模式"。

## 成本提示
派 5 个 sub-agent + 多次 CLI，单次较贵较慢——已由门控锁住，不在常规档触发。
