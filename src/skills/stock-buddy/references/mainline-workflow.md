# 主线工作流（v3 核心）

主线是 v3 系统的一等对象。本文件定义 stock-buddy 在主线生命周期各阶段的职责。生命周期与建页规则的事实源是 `投资笔记/05-主线追踪/README.md`，本文件只写**分析层怎么做**。

`提名` → `启动` → `发酵` → `分歧` → `警戒` → `退潮` → `归档`

> **`警戒` 是双钥匙结构引入的一档。**清仓级死亡条件必须是「**资金键 + 价格键**」双钥匙；**资金键单独成立只进 `警戒`**——冻结加仓 + AI 给上移止损建议（待用户确认），**不联动纪律①、不清仓**。纯价格条件可单键。规则事实源同上（`05-主线追踪/README.md`）。

**提名由 `stock-daily`（复盘）产出，不是本 skill 的活。**本 skill 负责三件事：提名答辩、主线体检、退潮复核。

---

## A. 提名答辩（用户对某条提名犹豫时）

触发：「这条主线靠谱吗」「值不值得跟」「帮我论证一下算力硬件链」。

输入：复盘里那条提名的叙事、证据、反方理由。

产出**结论先行的一页**，五段：

1. **裁决与 AI 建议**：`成立 / 观察 / 不成立` + 置信度 + 一句话理由；另给 `跟 / 暂缓 / 放弃` 倾向、证据权重与改判条件。
2. **正方证据链**：每条带数据日与来源。资金持续性至少要看**多日**，不能只用单日数据下「资金在流入」的结论——单日流入只证明当天有人买。
3. **反方**：不是走过场。至少给出「这条主线最可能怎么死」的具体路径。
4. **死亡条件建议**：可量化、可在复盘里自动判定的条件。写不出可判定的死亡条件 → **裁决只能是「观察」或「不成立」**，因为立项时必须先写死死亡条件。
   - **清仓级必须双钥匙**（资金键 + 价格键同时成立）；只给得出资金键的，那条只能是**警戒级**。
   - **必须附误报回测**：读本地板块逐日缓存——`python3 <stock-daily skill 目录>/scripts/board_fund_flow_cache.py history <板块代码> --limit 120 --end-date <数据日> --provider cache`——报告拟写的清仓级组合**在过去 60 个交易日触发几次**；**> 1 次即要求改写**。
     **缓存覆盖不足时**（新装的库只有很短的历史，概念与地域板块尤其容易只有寥寥数日）如实写 `误报回测未验证（缓存覆盖不足：仅 N 日）`，并把**裁决降为「观察」**：回测做不了就无法排除这条死亡条件是「一两周必炸」，**不得跳过该项直接建页**。
     依据：纯资金符号条件（连续 N 日净流出、聚合窗口转负）在板块逐日史上的底率高得惊人，且触发后的前向收益与不触发几乎无差别——**这类条件本身几乎不含信息**，靠它单独扣动清仓等于定期误杀。
   - **同轮给出退潮复核判据的预注册文本**（见 C 段），立项当轮就写进主线页，不等到「差一步触发」。判据**必须含至少一个非资金维度**，否则复核与触发同源、结构上不可能推翻触发。
5. **账户对照**：这条主线与现有持仓的重叠度。若已有机动仓压在同一风险因子上，必须明说「跟进等于加倍暴露」。

**裁决≠建页。**用户说「跟」才建页；本 skill 不擅自在 `05-主线追踪/` 建页。

## B. 主线体检（已立项主线的定期或临时复核）

触发：「XX 主线还活着吗」「这条主线怎么样了」。

1. 读该主线页的**死亡条件**、叙事、证据流、载体清单、我的操作。
2. 取最新数据核对：主线相关行业/板块的涨跌与资金（多周期）、载体表现、龙头是否还在领涨。
3. 判定当前阶段（启动 / 发酵 / 分歧 / **警戒** / 退潮）并给依据。
4. **逐条核对死亡条件是否触发**——这是体检的核心，不能只给感觉。
5. 若阶段有变化，把结论与依据写回主线页「证据流」——轨迹表插一行（最新在最上）+ 加一个默认折叠的明细块，两样都写——并同步 frontmatter 的 `阶段`；无变化则只在对话里回答，不写盘。

## C. 退潮复核（死亡条件疑似触发时）

复盘对死亡条件的判定是**单源机械触发**，退潮判定又直接联动纪律①（该主线全部机动仓退出），**误判代价高，本复核就是那道闸门**。

0. **先读该主线页的「退潮复核判据（预注册）」块，按它逐条判——不得另立标准、不得追加条件。**页里没有预注册块（双钥匙改造前立的老主线）才回退到下面第 2 步的定性判断，并在结论里注明「本案无预注册判据」。
1. 逐条列出死亡条件与当前实测值，明确哪条触发、哪条没触发；**并注明触发的是资金键还是价格键**。
2. 区分**真退潮**与**技术性回调**：看资金是持续净流出还是单日波动、宽度是否恶化、龙头是否走坏、催化剂是否证伪。
3. 给 `确认退潮 / 尚未退潮但恶化 / 虚警` 三档结论；只有资金键成立时，第三档写作 `虚警 · 降级警戒`。
4. **判为虚警（含降级警戒）时必须回退，不得让页面停在错误的退潮状态**——首页状态灯与后续复盘都靠 frontmatter 执法：
   - ① 回改主线页 frontmatter 的 `阶段` 字段到复核后的真实阶段（启动 / 发酵 / 分歧 / **警戒**）；
   - ② 在「证据流」补记一行轨迹 + 一个折叠明细块：`曾触发死亡条件 X，复核判虚警，理由…`（带数据与数据日）；
   - ③ **同轮提交**。
   判为「尚未退潮但恶化」同样按此回退 `阶段`，并在证据流（轨迹行 + 折叠块）写明恶化项与下次复核触发条件。
   判为 `虚警 · 降级警戒` 时另须写明**警戒态的硬动作**（冻结加仓 + 上移止损建议待用户确认）与**解除 / 升级条件**（连续 2 日资金键反向且收盘 > 触发日收盘 → 解除；任一日价格键落下 → 升级为真退潮）。
5. 确认退潮 → 明确给出 AI 建议：按纪律①退出该主线全部机动仓，并列出持仓卡里属于该主线的标的、支持证据、主要反方与改判条件。**建议不是委托，AI 不代下单。**
6. 用户确认后，主线页填「归档复盘」区（提名到退潮的完整证据链、判断对错、对未来提名质量的校准结论），移入 `05-主线追踪/归档/`，当轮提交。
7. **同轮建 T+N 复核档**（确认退潮才做）：
   - 主线页加「退潮判定 T+N 复核」一节（模板里有），记判定日读数、窗口机制签名、T+7 与 T+15 检查点日期（按真实交易日**写死**，不随行情顺延）；
   - 在 `05-主线追踪/归档/_退潮判定台账.md` 追加一行。分类判据已在该页预注册，**不得为了归类另换指标**。
   - **归为「误杀」不改变任何已执行的纪律动作**，不倒推、不追认、不构成买回信号，只进样本池。
   - 台账的用途是校准规则，不是校准单案：**攒够样本再改规则，任何单案结果都不触发规则修改**。

## 数据要求（三条都适用）

- 每个数字带**数据日与来源**；取不到写「未取得」，但**写之前必须走完 SKILL.md §数据源的「调用顺序」**：`a-stock-data`（零鉴权、无额度）→ `hithink-finance` CLI（额度独立于问财）→ 问财 `hithink-market-query`（**仅限正面清单内场景**：ETF 主题检索 / ETF 技术指标与资金流 / 复合条件筛股问句 / 复盘的涨跌家数四问句）。
- **单一通道失败或额度耗尽 ≠ 熔断**。三条通道都拿不到该数据项 → 该数据项熔断，写 `未取得（三源均失败：<逐条列出>）`，**任务其余部分照常完成**；整轮停止只在两种情况：① 关键数据项全部熔断致结论无依据；② 数据日异常或晚于系统当天。
- **调用顺序 ≠ 权威性，这是两条独立规则**。调用顺序管「先问谁省钱」；权威性管「同一数字多源冲突时听谁的」——`hithink-finance`（T1）> 问财（T2）> `a-stock-data`（T3），**T 编号表示权威性、不是调用顺序**。写入 vault 的数字若 T1 取得到则以 T1 为准并标注来源。
- 资金持续性看多周期（当日 / 5 日 / 10 日），`a-stock-data` §3.8 `board_fund_flow` 零额度提供行业×三周期。
- **板块逐日史的事实源是本地缓存，不是远端端点**：`stock-daily` 自带的 `scripts/board_fund_flow_cache.py`，存逐日主力净额、四档明细、净占比与**板块收盘点位**，每日收盘后由全板块当日快照增量续接。用于：误报回测 · MA20 等价格键计算 · 「连续 N 日」条件的断更回溯 · 退潮判定 T+N 复核回填。
  - 读取：`history <板块代码> --limit N --end-date <数据日> --provider cache`。**必须传 `--end-date` 锁定判定交易日**——行数够但末日不是判定日，等于拿旧数据冒充当日判定。
  - 行数不足、末日不匹配或跨源冲突 → 写 **`本项未验证`**，不得默认判「未触发」。**不同分类口径的板块序列不得互相拼接**——换口径等于改死亡条件本身。
- **极端流出判定必须板块内标准化**（z 分数或主力净占比），**禁止裸用全市场绝对额排名**——大成交额板块天然产出大绝对额，「全市场倒数第 N」主要反映体量与当日热度，不反映资金异常。
- **锚点的立项日取值必须与后续判定同源同接口**，两源口径差会污染整条判定序列。
- 行业分类口径不同的来源（同花顺行业 vs 东财行业）分别标注，不混算。
- 输出末尾固定：`本工具仅用于研究与决策支持；提供方非持牌证券投资咨询机构，本工具及其输出不构成投资建议，不代下单，使用者风险自担。数据来源：<本次运行实际使用的数据源>；数据日：YYYY-MM-DD，均以本次运行输出为准。`

## 写盘边界

| 动作 | 谁做 | 何时 |
|---|---|---|
| 提名 | `stock-daily` 复盘 | 每个交易日 |
| 建主线页 | 用户拍板「跟」后，当轮建页并提交 | 仅此一种情况 |
| 证据流增量（轨迹行 + 折叠明细块） | `stock-daily` 日更；本 skill 在体检发现阶段变化、或退潮复核判虚警/尚未退潮时写（同步回改 frontmatter `阶段`） | — |
| 载体清单 | `stock-screener` 载体筛选产出，本 skill 做账户适配后写回 | 见 `selection-handoff.md` |
| 参考条件位 | 本 skill（专家模式或常规档深度论证） | 载体确定后 |
| AI 决策建议 / 估值区间 / AI 仓位建议 | 本 skill 金融专家模式 | 有可审计输入时 |
| 归档复盘 | 本 skill 在退潮复核确认后 | 退潮时 |
| 退潮复核判据（预注册） | 本 skill 在提名答辩时给出文本，建页当轮写入 | 立项时 |
| 「退潮判定 T+N 复核」一节 + `归档/_退潮判定台账.md` 追加一行 | 本 skill 在退潮复核确认后**同轮**建档；此后 T+1…T+7 由 `stock-daily` 复盘顺手填 | 退潮时建档，逐日回填 |

**v3 不再写**：`07-交易决策/`、`08-下个交易日/`、`06-交易记录/`（均已归档）。决策内容（条件位、失效条件）并入主线页；用户报成交只更新持仓卡与主线页「我的操作」区。
