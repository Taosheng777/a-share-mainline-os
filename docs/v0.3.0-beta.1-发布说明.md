# v0.3.0-beta.1 发布说明

上一版把仓库从“可以安装”推进到“可以安全升级、公开复现”。这一版改的是**判断本身**：主线退潮从“单钥匙机械触发”改成“双钥匙 + 警戒态 + 回头验证”，并把判定逻辑从散文规则收敛成可回放的确定性实现。

## 为什么改

旧结构里，**纯资金符号条件可以单独扣动清仓**——「连续 N 日主力净流出」「5 日聚合转负」成立，就直接判退潮、联动清仓纪律，中间没有任何确认环节。

问题不在某一次判错，而在这类信号的**误报底率**：在板块逐日历史上跑一遍，它们隔几个交易日就会新触发一次，且触发后的前向收益与不触发几乎没有区别——**信号本身几乎不含信息**。把它接到一个不可逆动作上，等于给系统装了一个定期误响的清仓警报。真正的代价是：人会因此在关键时刻不再信任触发器，那才是纪律真正的死法。

所以这一版的定位要说清楚：**双钥匙是安全结构，不是已被证明有效的退潮预测器。**它降低单源低特异度信号直连不可逆动作的概率，不声称提高了预测精度；现役阈值也不因任何一次回测结果事后调参。

## 主要变化

### 判定结构

- **双钥匙死亡条件**：清仓级条件必须「**资金键 + 价格键**」同时成立。立项时预注册的**纯价格条件仍可单键触发**。
- **新增 `警戒` 阶段**：资金键单独成立时判 `警戒` 而非 `退潮`。动作硬且可逆——冻结加仓 + AI 给上移止损建议（待用户确认），**不联动清仓纪律**；用户未确认前，单笔止损线仍按原止损位执行。解除条件是连续 2 个交易日资金键反向且收盘高于触发日收盘；期间任一日价格键落下即升级为退潮。
- **判定规则版本**：主线页 frontmatter 写 `判定规则版本`。`double_key_v1` 走双钥匙；没有该字段的旧页按 `legacy_any` 与页面原文执行，**不得代为升级或降级**。

### 确定性实现与回放

- 新增 `stock-daily/scripts/mainline_validation.py`：退潮判定真值表（`classify_retreat`）、提名影子观察（`assess_nomination_shadow`）、次日证伪（`assess_next_day_falsification`），以及板块历史回放与预注册验收 Gate。
- **缺数据 fail closed**：任一必需键缺失返回 `unverified / data_block`，不得静默当成「未触发」。
- 随仓库发布一组结构化行为案例（`tests/fixtures/mainline_cases.json`），覆盖资金键单独成立、聚合窗口同类读数、双键同日成立、未预注册的价格半边、已预注册的纯价格单键、提名影子三旗全亮、次日证伪成立。**改判定语义就要同轮补案例**，离线门会跑这套回放。

### 回头验证

- **退潮复核判据预注册**：立项当轮就写进主线页，规定触发后按什么判，**触发当天不得追加或修改**。判据必须含至少一个非资金维度，否则复核与触发同源、结构上不可能推翻触发。
- **退潮判定 T+N 台账**：每次判定建一行，T+7 按预注册判据机械归类，T+15 终裁；检查点日期建档时写死，不随行情顺延。样本计数只数**真的执行了纪律①**的判定。
- **复活哨**：已归档主线在判定日后 15 个交易日内，若锚板块连续 2 日主力净流入且收盘高于判定日收盘，复盘必须置顶「疑似误杀提示」。它是**请用户决定是否重新评估，不是买回信号**；归类为「误杀」不倒推、不追认任何已执行的纪律动作。
- **修订窗口预承诺**：结构与判据定稿即冻结，攒够预定样本量或走到预定日期才校准。**此前任何单案结果都不触发规则修改。**

### 数据层

- **随仓库发布板块逐日缓存** `stock-daily/scripts/board_fund_flow_cache.py`（**本仓库自有代码，不属于上游 `a-stock-data`**）：把全板块逐日主力净额、四档资金与板块收盘点位存进本地 SQLite。它是 MA20 价格键、「连续 N 日」条件回溯、立项误报回测和 T+N 回填的前提。
- 复盘前置新增一步幂等快照续接。**本 Skill 只调用，永不替用户创建定时任务或后台监控**——用户想提前跑可自行在系统里排。
- 缓存是逐日累积的，新装时历史很短。**覆盖不足、末日不匹配或跨源冲突一律写「本项未验证」**，不默认判「未触发」，也不阻断其余复盘区。

### 提名与筛选

- 每条正式提名强制记四项 `shadow_only` 观察：涨停梯队映射、A 股催化落点、锚板块名次稳定性、次日证伪条件。四项**不阻断提名裁决**；但涨停零映射与无 A 股催化落点同时出现时，必须标注「A 股执行链未验证，证据高风险」，不得包装成「A 股承接已成立」。
- **立项误报回测成为强制项**：拉锚板块 120 日逐日史，报告拟写的清仓级组合在过去 60 个交易日触发几次，**> 1 次即改写条件**；回测做不了就把裁决降为「观察」，不得跳过。
- 死亡条件写法卫生三条：极端值必须**板块内标准化**（禁止裸用全市场绝对额排名）；锚点立项日取值必须与后续判定同源同接口；纯资金符号条件不得单独扣动清仓。
- `stock-screener` 的载体排序 T+N 跟踪把 **Spearman 秩相关列为固定指标**：批均为正而秩相关为负，说明赚的钱和打分无关。载体不足 3 只写「样本不足」；**单批噪声极大，不得据单批下任何结论**，打分排序能力在被累计样本验证为正之前只能当作待验证假设。

## 兼容性

- **不迁移、不覆写任何用户 vault 内容。**已有主线页没有 `判定规则版本` 字段的，按 `legacy_any` 与页面原文继续执行，系统不会代为升级或降级。
- vault 模板新增的区块（退潮复核判据、立项影子观察、载体排序 T+N 跟踪、退潮判定 T+N 复核）只影响**新建页**。
- 升级只替换三个 Skill；用户 config 与 vault 永不进入覆盖范围。
- `v0.1-beta` 与 `v0.2.0-beta.1` 的历史 tag 与附件保持不变。
