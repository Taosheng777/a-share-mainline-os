# 升级与回滚

升级器只管理 `stock-daily`、`stock-screener`、`stock-buddy` 三个 Skill。它不会读取或修改 `ASM_CONFIG`、个人 vault、纪律卡、持仓或盘面日志。

## 升级前预览

Codex：

```bash
bash adapters/codex/install.sh --upgrade --dry-run
```

Claude Code：

```bash
bash adapters/claude/install.sh --upgrade --dry-run
```

确认目标目录与三个 Skill 名称后，去掉 `--dry-run` 执行。已有 `ASM_FORCE_INSTALL=1` 调用仍兼容，但新版本推荐显式 `--upgrade`。

## 备份与失败恢复

升级前，三个旧 Skill 会进入同一批次目录：

```text
<skills-root>/.a-share-mainline-os/backups/<批次>/skills/
```

只有新分发树通过 frontmatter 与完整性检查后才替换。替换中途失败会自动恢复原目录；安装记录位于 `<skills-root>/.a-share-mainline-os/install.json`。

## 回滚

```bash
bash adapters/codex/install.sh --rollback --dry-run
bash adapters/codex/install.sh --rollback
```

Claude Code 用户替换脚本路径。回滚恢复最近一次升级前实际存在的 Skill，不触碰 config 与 vault。完成后新建任务，让 Agent 重新加载 Skill。

## 升级后检查

```bash
python3 scripts/doctor.py --platform codex
```

Claude Code 使用 `--platform claude`。`doctor` 只读检查 Python、三个产品 Skill、安装版本、配置、vault 合同和 `a-stock-data`；可选数据源缺失不阻塞。

## Vault 模板

`vault-template/.a-share-mainline-os.json` 只声明模板 schema 与版本。升级器永不把新版模板覆盖到用户 vault。未来若模板需要迁移，必须提供独立迁移说明、预览和用户确认。
