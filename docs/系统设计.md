# 系统设计

## 核心对象

系统围绕“主线”而不是账户建立事实链。主线从提名开始，依次进入启动、发酵、分歧或退潮，最后归档。每条已立项主线都必须预注册死亡条件，证据流按数据日增量追加。

## 三层决策合同

1. **纪律层**：只读 vault 的 `01-纪律卡.md`，阈值为空就不可判定；AI 不得代填。
2. **AI 建议层**：给明确行动倾向、证据、主要反方与改判条件。专家模式只有在输入可审计时才给目标区间和风险预算仓位。
3. **用户执行层**：用户确认并自行交易；系统不代下单、不产生委托，也不把 AI 技术位冒充用户确认的纪律止损。

## 三个 Skill

- `stock-daily`：最新交易日的盘面、主线、持仓五区复盘；断更零债务。
- `stock-screener`：给已立项主线筛 ETF 与龙头股，做相关度校验和四维排序；只筛不分析。
- `stock-buddy`：主线论证、退潮复核、标的与持仓分析；专家模式必须收齐五个独立维度。

## 单一事实源与平台适配

公开 Skill 的单一事实源是仓库内 Claude-compatible 的 `src/skills/`。`scripts/export_from_source.py` 按 `config/export-manifest.json` 白名单生成 Claude 与 Codex 两棵分发树；Codex 的 `collaboration` 工具名和门控表述只由窄适配器改变。`--check` 会在临时目录重建两棵树并逐字节比较，任何公开 clone 都能复现，作者私人运行目录不参与公开构建。

用户安装目录、`~/.config/a-share-mainline/config.json` 与个人 vault 是运行态，不是产品 source。安装器只替换三个 Skill；升级备份和安装记录位于 Skill 根目录下的 `.a-share-mainline-os/`，不会迁移或覆盖用户事实。

## 数据降级

调用顺序固定为 `a-stock-data` → `hithink-finance` → 问财，目的是优先使用低成本通道；同一数字冲突时权威性为 `hithink-finance` > 问财 > `a-stock-data`。单通道失败只降级，三源都失败才把该数据项标为“未取得”。

`a-stock-data`、`hithink-finance`、问财和 iFinD helper 都是外部组件；发行包不附带其源码、凭据或数据。
