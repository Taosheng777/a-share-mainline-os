# 〈主线名〉

## ■ 状态头

| 项 | 内容 |
|---|---|
| 当前阶段 | 提名 / 启动 / 发酵 / 分歧 / **警戒** / 退潮 / 归档 |
| 立项日 | YYYY-MM-DD（用户拍板「跟」的日期） |
| 第 N 个交易日 | N（自立项日起的 A 股交易日计数） |
| **死亡条件 · 清仓级**<br>（触发即联动纪律①全仓退出） | 立项时必须先写死，且逐条通过「断更可判定」自检 + 误报回测。**必须是双钥匙**：**资金键**（5 日主力转负 / 5 日排名跌出前 N / 连续 N 日净流出 / 板块内 z ≤ −2 …）与**价格键**（当日收盘 < MA20，**或** < 基线触发线）**同时成立**才算触发。<br>**例外**：纯价格条件（「板块指数较基线回落超 N%」这一式）**可以单键**——它本身就是价格键。催化剂证伪类条件按「证伪点」处理，不单独作为清仓级条件。 |
| **死亡条件 · 警戒级**<br>（资金键单独成立） | **动作硬且可逆，不是「无动作」**：① 本主线**冻结加仓**；② 若有持仓，AI 当轮给出**上移止损建议**（待用户确认；未确认前纪律②仍按原止损位执行）。<br>**解除**：此后连续 2 个交易日资金键反向（主力为正）**且**收盘 > 触发日收盘 → 解除警戒，回改 frontmatter `阶段` 并在证据流补记一行。<br>**升级**：警戒期间任一日**价格键落下** → 转清仓级，执行纪律①。 |
| **立项误报回测**（强制项） | 立项时**必须**读取锚板块 120 日逐日缓存，报告拟写的**清仓级组合在过去 60 个交易日的触发次数**；**> 1 次即要求改写条件**。杜绝再立一条「一两周必炸」的死亡条件。结果写在本行：`清仓级组合过去 60 日触发 N 次（回测数据日 YYYY-MM-DD）`；缓存覆盖不足时写 `误报回测未验证（缓存覆盖不足：仅 N 日）` 并把裁决降为「观察」。 |
| **基线三要素** | 凡涉及**指数或价格阈值**的死亡条件（含**每一条清仓级条件的价格键**），立项时必须逐条在此记录：**标的或指数代码 · 基线点位 · 基线数据日**。**缺任一项则该条件不可判定，不得写入。** |
| **判定规则版本** | `double_key_v1`。无此字段的旧页按 `legacy_any` 与页面原文执行，**不得静默改写历史**。 |

> **板块逐日主力资金史的口径**：统一读 `stock-daily` 自带的 `scripts/board_fund_flow_cache.py` 缓存，并用判定交易日作 `--end-date` 强 Gate。缓存由收盘后的全板块快照续接。
> 三个后果：① **「连续 N 日」条件可用**（断更后可回溯），不必强迫死亡条件只写聚合窗口；② 立项误报回测成立；③ 退潮判定的 T+N 复核可随时回填。**但仍须写清回溯数据源与数据日**——凡用「连续 N 日」，必须在同一行写明读的是哪个板块缓存、截至哪个交易日。

> [!warning] 死亡条件写法卫生（三条，强制）
> 1. **极端值判定必须板块内标准化**（z 分数或主力净占比），**禁止裸用全市场绝对额排名**。大成交额板块天然产出大绝对额资金流，「全市场倒数第 N」主要反映板块体量与当日热度，不反映异常程度——同一个「倒数前几名」的绝对额，换算成板块内 z 分数往往连 −1.5 都不到。
> 2. **锚点的立项日取值必须与后续判定同源同接口。**立项值取自 A 源、后续判定走 B 源，两源口径差会污染整条判定序列。
> 3. **纯资金符号条件不得单独扣动清仓。**这是双钥匙结构存在的唯一理由：资金符号条件的**误报底率**决定了任何被持有超过两周的主线几乎必然被它击杀一次，与主线健康与否无关。

## ■ 死亡条件的实证依据（模板说明，建页时可整段删除）

> [!warning] 双钥匙是安全结构，不是已验证的预测器
> 在**全池、长窗口**上跑纯资金符号条件，容易得到一个看起来漂亮的负收益中位数。但把样本**限定到真正会被立项的对象**（高波动、刚爆发的板块事件）后，这类条件与基线的区分度会大幅塌缩——预注册的支持 Gate 未必通过。
> 因此本模板对双钥匙的定位是：**冻结期内防止低特异度单源信号直连不可逆动作的安全结构**，不是已被证明有效的退潮预测器。**现役阈值不因某一次回测结果事后调参。**
> 想在自己的数据上复核：`python3 <stock-daily skill 目录>/scripts/mainline_validation.py study --db <缓存库路径> --output-dir <输出目录>`。**Gate 一旦预注册就不得按结果改门槛**；失败后追加的切片只能标 `post_gate_diagnostic_only`。

## ■ 退潮复核判据（预注册）

> [!danger]+ 退潮复核判据 · 〈预注册日 YYYY-MM-DD〉（**立项当轮就写**，只规定怎么判、不预设判成什么）
> **死亡条件、基线三要素、计数一个字都不动。**本块只规定清仓级条件触发后 `stock-buddy` 退潮复核**按什么判**。**触发当天不得追加或修改本块任何一条。**
>
> **适用范围**：〈哪几条清仓级条件触发时走本复核〉。**纯价格条件不走本复核**——它本身就是价格键，跌破即直接判真退潮。
>
> **三条判据，全部成立才可判「虚警 · 降级警戒」；任一不成立即判真退潮：**
>
> | | 判据 | 立项日读数（参照用） |
> |---|---|---|
> | **(a) 价格键** | 锚板块当日收盘 **> 当日 MA20**，**且 > 基线触发线** | |
> | **(b) 窗口机制** | 剔除窗口内**主力净额最负的一日**后，窗口净额**为正**（转负由单日极端值或单日滚出主导 = 窗口伪影） | |
> | **(c) 资金位置** | 本主线锚板块**至少一个** 5 日资金排名仍在**前 N** | |
>
> **(b) 剔的是「最负的一日」，不是「绝对值最大的一日」**——后者往往是大流入日，剔掉只会让窗口更负，检验方向是反的。
> **判「虚警 · 降级警戒」后的硬动作**、解除与升级条件，按状态头「死亡条件 · 警戒级」那一行执行。
> **数据源**：判定用当日全板块快照与排名；回溯、MA20 与断更回填统一读本地板块逐日缓存。MA20 锚在**板块指数**，不是载体 ETF。缓存覆盖不足、末日不匹配或跨源冲突时写「本项未验证」。

> **为什么必须在立项当轮写、而不是等触发前一刻**：临触发才注册的判据，几乎必然全部锚在资金与排名上，**与触发信号同源**，结构上不可能推翻触发——复核闸门形同虚设。判据里必须至少有一个**非资金维度**（价格键），且不能被 AND 结构淹没。

> [!warning] **秩相关是固定指标，不是可选项**
> 记 **Spearman 秩相关（载体排序 vs 区间收益）**，**不能只记批均收益**——批均为正而排序为负，说明赚的钱和打分无关，那时「排序第 1」这个结论是假的。
