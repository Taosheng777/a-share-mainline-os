# 主线追踪

主线是一等对象，生命周期为：提名 → 启动 → 发酵 → 分歧 → 警戒 → 退潮 → 归档。

## 生命周期

| 阶段 | 谁判定 | 判定依据 |
|---|---|---|
| 提名 | AI 提，用户拍板 | 复盘给 0–3 条候选，附证据、反方与死亡条件雏形。用户说「跟」才建页 |
| 启动 / 发酵 / 分歧 | 每日数据机械判定 | 证据流记一行轨迹（阶段 + 死亡条件锚点当日值）+ 一个折叠明细块 |
| 警戒 | **资金键单独触发**，或清仓级触发后复核判为「虚警 · 降级警戒」 | 动作硬且可逆：冻结加仓 + AI 给上移止损建议（待用户确认）。**不联动纪律①，不清仓**。解除：连续 2 个交易日资金键反向且收盘 > 触发日收盘。升级：期间任一日价格键落下 → 转退潮 |
| 退潮 | 触发该页预写的**清仓级死亡条件**（**资金键 + 价格键双钥匙**；纯价格条件可单键） | 退潮判定 = 纪律 ① 主线失效退出 的触发信号，直接联动持仓对照 |
| 归档 | 退潮后封存 | 含全程复盘与「退潮判定 T+N 复核」建档，移入 `归档/` |

## 建页规则

- 立项时**必须先写死亡条件**，没有死亡条件的主线不建页。
- **清仓级死亡条件必须是双钥匙**（资金键 + 价格键同时成立）；资金键单独成立只进警戒。纯价格条件可单键。
- **立项误报回测是强制项**：拉锚板块 120 日逐日史，报告拟写的清仓级组合在过去 60 个交易日的触发次数，**> 1 次即改写条件**。缓存覆盖不足时如实写「误报回测未验证」，并把裁决降为「观察」。
- **退潮复核判据在立项当轮就预注册**（不是等到「差一步触发」才写）——判据必须含至少一个**非资金维度**，否则复核与触发同源、结构上不可能推翻触发。
- 新建页在 frontmatter 写 `判定规则版本: double_key_v1`。没有该字段的旧页按 `legacy_any` 与页面原文执行，**不得代为升级或降级**。
- AI 提名必须给证据、反方和可判定的死亡条件雏形。
- 触发不等于执行；系统只提示，不下单。

> **为什么要加「警戒」这一档**
> 旧结构里纯资金符号条件可以单独扣动清仓，中间没有任何确认环节。而这类条件（连续 N 日净流出、聚合窗口转负）在板块逐日史上的**底率极高**，触发后的前向收益与不触发几乎无差别——**信号本身几乎不含信息**。
> 警戒态不是给「留仓」找豁免票，它是为了保住「触发必执行」的权威性：一个隔几天就误响一次的清仓信号，迟早会教会人在关键时刻不信任触发器，那才是纪律真正的死法。**任何条件都不因叙事被豁免。**
> 因此双钥匙的定位是**冻结期内防止低特异度单源信号直连不可逆动作的安全结构**，**不是已被证明有效的退潮预测器**。想自己复核，用 `stock-daily` 的 `mainline_validation.py study` 在自己的板块缓存上跑回放。

### 立项影子观察（每条提名与新页强制采集）

缺失写 `未验证`，不得省略：

1. **涨停梯队映射**：当日涨停股中能映射到该主线的数量与名单。
2. **A 股催化落点**：催化是否落到具体 A 股上市主体、订单、产品验证或业绩事件；写 `是 / 否 / 未验证` 并列主体与证据。
3. **锚板块名次稳定性**：锚板块成分数；成分 `<50` 且死亡条件依赖全市场绝对名次时标 `narrow_absolute_rank_anchor`。
4. **次日证伪条件**：提名当轮预写一条下一交易日可机械核对的反向条件，次日填 `未证伪 / 已证伪并退回观察 / 未验证`。

四项统一标记 `shadow_only`，**不自动改写提名裁决、死亡条件或退潮阈值**。但若同时出现 `zero_limit_up_mapping` 与 `no_a_share_catalyst_landing`，输出必须醒目标注 **「A 股执行链未验证，证据高风险」**，不得包装成「A 股承接已成立」。

## 退潮判定的验证与复活

载体排序早有 T+N 跟踪，**退潮判定本身容易没有任何回头验证机制**——判定当天完成、次日执行、然后再无下文；资金反转时也没有机制提示「判定依据已经反转」。**死亡机械且快，复活全靠人手一动不动**，这是不对称的。两条补丁：

1. **退潮判定 T+N 台账**（`归档/_退潮判定台账.md`）——每次退潮判定建一行，T+7 按预注册判据机械归类（误杀 / 正确 / 未定），T+15 终裁。检查点日期建档时**写死**，复盘顺手填，断更用板块逐日缓存回填。
2. **复活哨**——已归档主线在判定日后 15 个交易日内，若锚板块连续 2 日主力净流入且收盘高于判定日收盘，**次日复盘 ②区必须置顶「疑似误杀提示」**。提示的动作是**请用户决定是否重新评估**，不是买回信号；重评走新立项流程（新页、新死亡条件、新基线）。

**归类为「误杀」不改变任何已执行的纪律动作**，不倒推、不追认、不补偿，只进样本池。

## 修订窗口（预承诺）

模板、双钥匙结构与复核判据一经定稿就**冻结**，直到台账攒够预定样本量或走到预定日期（先到为准）才开校准会。**在此之前任何单案结果都不触发规则修改。**

这是对「N=1 不许过拟合」的正面回应：**不是永远不改，是按预定的样本量和日期改。**同时划清界线——不许做的是「把 2 日改成 4 日」这类看着某一案调阈值；许做的是修「单源低特异传感器直连不可逆动作」这类结构缺陷，判别标准是**该修改在不知道结果时是否同样成立**。

**现役主线的死亡条件、基线与计数一字不动**：结构改动只作用于**未来立项**与**判定之外的验证层**。

## 证据流

证据流每天写**两样**，缺一不算完成：

1. **轨迹行**——固定 4 列 `数据日 | 阶段 | 死亡条件锚点当日值 | 一句话结论`，**最新插在最上面**。锚点列与状态头死亡条件逐条对应，**未触发也要写当日值**，这一列就是判定生死的时间序列。
2. **折叠明细块**——`> [!note]- YYYY-MM-DD 明细 · 〈阶段〉`，按 资金 / 涨幅 / 宽度 / 载体 / 来源 分行。结尾的 `-` 是默认折叠开关。

**只写本主线自己的判定依据。**全市场指数、涨跌家数、行业总榜、成交额已在当日复盘里，此处只链接、不转录。每行必须带数据日与来源；阶段变化时保留旧证据，不静默覆盖。

## 板块逐日史的口径

统一读 `stock-daily` 自带的 `scripts/board_fund_flow_cache.py` 缓存，并用 `--end-date` 锁定判定交易日。缓存缺口不得用远端零散补数掩盖；行数不足、末日不匹配或跨源冲突一律写「本项未验证」，**不得默认判「未触发」**。不同分类口径的板块序列不得互相拼接。
